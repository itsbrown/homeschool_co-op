# ADR-001: Chat-first parent concierge on the Express app

**Status:** Implemented in Phase 1 (`POST /api/concierge/chat`, migration `268-concierge-events.sql`). Not merged. Not deployed.
**Date:** 2026-10-09 (design). Implemented 2026-10-10.

## Context

Parents already have a Vite route, `/parent/concierge`, inside `ParentAppShell`. The matching Express router (`server/api/parent-concierge.ts`) is not mounted, calls Anthropic with `@anthropic-ai/sdk`, and can see payments, credits, and the cart. That is the wrong contract.

The app is Vite + Express + Drizzle. It is deployed as an Express process (Replit Reserved VM in production), not as a Next.js app on Vercel. Auth is a Supabase JWT checked in Express. The live Auth project is `moivwjuglwwfrhqeewju` (Auth only; never pause). ASA Platform Prod and ASA Platform 2026 hold no live data. Family rows are in the app's Postgres on Replit (`DATABASE_URL`), keyed by `users.id`. Whether that database is Replit-managed or Neon is still unconfirmed.

## Decision

Build the concierge as a **chat-first page** on the existing Vite route. The model runs through the **Vercel AI SDK** (`ai`) and **Vercel AI Gateway**. Tools are server-side, on an Express route mounted from `server/index.ts`, behind `supabaseAuth`.

### Recommendation: Express route, not a second Vercel deploy

| Option | Fit |
|--------|-----|
| **Express route (chosen)** | Reuses `supabaseAuth`, `req.user.id`, Drizzle, and the storage methods that already scope a parent to their children. The Vite page keeps calling `/api/...` with `apiRequest`. AI Gateway is an outbound HTTPS call (`AI_GATEWAY_API_KEY`); the SDK does not require Next.js. |
| Separate Vercel deploy | Would be a second app with its own `DATABASE_URL`, a second copy of the Supabase JWT check, and CORS between the Vite origin and the chat host. The parent session already lives on the Express origin. A second deploy is a second place to forget the family filter. |

Other assistants in this repo stay on `@anthropic-ai/sdk` until they are deliberately moved. This ADR does not change them. Gateway model choice is an env setting, not a new framework.

### Tools

The model may call only these tools. Each tool ignores any parent id, email, or child id that the model supplies and loads the family from `req.user.id`.

| Tool | Behavior |
|------|----------|
| `get_my_family` | The signed-in user plus children where `children.parent_id = req.user.id` or `child_guardians.guardian_user_id = req.user.id`. Names, grade, campus, and enrollment status the parent already sees. No Stripe ids, balances, or medical fields unless a later, explicit product decision says otherwise. |
| `get_week_materials` | Published `week_plan_blocks` for those children's enrolled classes for the requested week. Same enrollment → class rule as `GET /api/schedule-builder/parent/my-week-plans` (`marketplace_class_id ?? class_id`). |
| `rsvp_event` | RSVP the signed-in parent to a store event (`store_products.product_kind = 'event'`). A price of 0 may be recorded. Any non-zero price, a Stripe call, or a change to another family's RSVP is not performed. The tool returns a handoff instead. |
| `start_enrollment_inquiry` | Does not write `program_enrollments`, does not add a cart line, and does not register a child. Sends the parent's question and contact info to **Corey** through SendGrid. |

`check_payments`, `check_credits`, `add_to_cart`, and `register_child` from the unmounted Anthropic router are not part of this design.

### Leads

`start_enrollment_inquiry` sends mail with the existing helper in `server/lib/email-service.ts`. Recipient: `CONCIERGE_LEAD_EMAIL` (Corey). Provider must be SendGrid (`SENDGRID_API_KEY`). If SendGrid is not configured, the tool fails visibly and does not fall through to Brevo. The email is a lead for a person, not an enrollment.

### Analytics

Every chat turn and every tool call is an analytics event:

| Event | When |
|-------|------|
| `concierge_turn` | One parent message in, one assistant reply out |
| `concierge_tool` | Each tool invocation, with tool name, ok/error, and latency |

These rows are **not** inserted into `user_activity_events` or `checkout_funnel_events`. The activity check constraint cannot store these types, and that table feeds engagement slices by child age and gender. Phase 1 adds `concierge_events` in `server/migrations/268-concierge-events.sql` (268, because unmerged school-setup work already claimed 267). Columns: `school_id`, `user_id`, `event_type`, `tool_name`, `ok`, `latency_ms`, `metadata` jsonb. `sanitizeConciergeMetadata` drops keys that look like birthdate, medical text, allergies, child name, email, or a marketing segment, and drops strings longer than 64 characters. Do not export these rows to Brevo or `marketing_links`. A failed insert does not fail the chat reply; the JSON response sets `analyticsLogged: false`.

## Consequences

- The Vite page can stay chat-first. "Browse on your own" continues to land on `/parent/home`, not back on `/dashboard` when that route is the concierge.
- Gateway credentials live on the Express host, next to `ANTHROPIC_API_KEY`, not only in a Vercel project.
- Implementers must not mount the current `parent-concierge.ts` router as-is.
- Schema work, when it comes, is a new SQL file. Not `db:push`.
